# Security Policy

Security is a priority. We expect all reports to be handled responsibly, privately, and without public disclosure.

## Reporting a vulnerability

Do not report security vulnerabilities in public GitHub issues or repository discussions.

If the repository supports private vulnerability reporting, use that workflow. Otherwise, contact the maintainers through the private channel designated for this project.

Include the following information when possible:

- affected file or component
- a clear description of the vulnerability
- reproduction steps or proof of concept
- expected and actual impact
- any mitigation already in place

## Disclosure expectations

We expect reporters to allow a reasonable time for investigation before any public disclosure is made. Publicly discussing a security issue before it is fixed is not acceptable.

## Scope

This policy applies to the JARVIS repository and the code maintained within it.

## Final note

Responsible disclosure helps protect users, contributors, and the project itself.
